# I2S Audio Cluster

**Битсинхронный многоканальный I2S аудио кластер для активных акустических систем**

Масштабируемая многоканальная аудиоплатформа на базе [Luckfox Pico MAX](https://wiki.luckfox.com/Luckfox-Pico-Pro-Max) (Rockchip RV1106). Несколько нод объединяют тактовые сигналы I2S через физическое соединение, что гарантирует **побитовую синхронизацию** всех каналов — критично для активных многополосных акустических систем.

## Ключевые особенности

- **Побитовая синхронизация** — все ноды объединяют BCK/LRCLK/MCLK через провода, обеспечивая нулевой дрейф семплов между каналами
- **Масштабируемость** — до 16 slave-нод (128 каналов), ограничено только возможностями HQPlayer
- **8 каналов на ноду** — 4 стерео линии данных I2S (SDO0–SDO3)
- **PCM до 32bit/192kHz** — гарантированно (8 каналов на ноду)
- **PCM до 32bit/384kHz** — в режиме 4 канала на ноду
- **DSD до DSD256** — нативное воспроизведение с автоматическим переключением PCM/DSD
- **Гибкое тактирование** — внешние генераторы (режим EXT) или встроенный PLL RV1106 (режим PLL). Встроенный PLL обеспечивает на удивление высокое качество звучания — некоторые аудиоэксперты отдают ему предпочтение перед дорогими внешними аудиоклоками
- **Два тактовых домена** — семейства 44.1kHz и 48kHz с автоматическим переключением генераторов через GPIO
- **Bit-perfect** — без ресемплинга, без микширования, прямой путь DMA → I2S
- **Сетевое аудио** — протокол [HQPlayer NAA](https://www.signalyst.com/naa.html) через Ethernet

## Зачем это нужно для активных АС

В многополосной активной акустической системе каждая полоса (ВЧ, СЧ, НЧ, сабвуфер) управляется отдельным каналом ЦАП. Любое временное смещение между каналами вызывает:

- Фазовые ошибки на частотах раздела кроссовера
- Артефакты гребенчатой фильтрации
- Ухудшение стереообраза

Кластер гарантирует **нулевую межканальную временную ошибку**, поскольку все ноды используют одни и те же физические тактовые сигналы I2S. ЦАПы на каждой ноде видят идентичные фронты BCK/LRCLK одновременно.

## Аппаратное подключение

### Распиновка сигналов I2S (Luckfox Pico MAX)

| Сигнал | GPIO | Пин | Направление (Master) | Направление (Slave) |
|--------|------|-----|--------------------|-------------------|
| BCK (Bit Clock) | GPIO2_A0 | 24 | Выход | **Вход** |
| LRCLK (Frame Clock) | GPIO2_A1 | 25 | Выход | **Вход** |
| MCLK (Master Clock) | GPIO2_A2 | 26 | Выход | **Вход** |
| SDO0 (Данные ch0-1) | GPIO2_A4 | 21 | Выход | Выход |
| SDO1 (Данные ch2-3) | GPIO2_A7 | 34 | Выход | Выход |
| SDO2 (Данные ch4-5) | GPIO2_A6 | 29 | Выход | Выход |
| SDO3 (Данные ch6-7) | GPIO2_A3 | 27 | Выход | Выход |

### Распиновка управляющих сигналов

| Сигнал | GPIO | Пин | Функция |
|--------|------|-----|----------|
| MUTE | GPIO1_D3 | 10 | Отключение звука (активный высокий) |
| MUTE_INV | GPIO3_C6 | 22 | Инвертированный mute (активный низкий) |
| DSD_ON | GPIO1_D0 | 19 | Включение режима DSD |
| MCLK_SEL | GPIO1_D1 | 20 | Выбор тактового домена (44.1/48kHz) |
| FREQ_INV | GPIO1_C5 | 6 | Инвертированный выбор тактового домена |
| HI_RES | GPIO1_C6 | 5 | Индикатор Hi-Res (активен при 352.8/384 кГц) |
| HW_SYNC | GPIO1_C7 | 4 | Провод синхронизации старта: master OUT → slave IN |

### Соединение нод

Соедините **master → все slave** короткими проводами (рекомендуется < 5 см):

```
Master                      Slave
──────                      ─────
BCK     (GPIO2_A0, пин 24) ──────► BCK     (GPIO2_A0, пин 24)
LRCLK   (GPIO2_A1, пин 25) ──────► LRCLK   (GPIO2_A1, пин 25)
MCLK    (GPIO2_A2, пин 26) ──────► MCLK    (GPIO2_A2, пин 26)
HW_SYNC (GPIO1_C7, пин  4) ──────► HW_SYNC (GPIO1_C7, пин  4)
GND     ──────────────────────────── GND
```

**Важно:**
- Все три тактовые линии (BCK, LRCLK, MCLK) должны быть соединены
- Провод HW_SYNC обеспечивает побитно-точный одновременный старт на всех нодах — соедините пин 4 master со всеми slave пин 4
- Общая земля (GND) обязательна
- Провода должны быть короткими и одинаковой длины для минимизации перекоса
- Линии данных (SDO0–SDO3) идут к собственному ЦАП каждой ноды — они НЕ разделяются между нодами
- MCLK_SEL и DSD_ON можно объединить, если все ноды используют одинаковую конфигурацию ЦАП

### Внешний тактовый генератор (режим EXT)

В режиме EXT мастер-нода получает MCLK от внешнего генератора или тактового выхода ЦАП. Используются два генератора:

| Генератор | Частота (512fs) | Частота (1024fs) | Тактовый домен |
|-----------|-----------------|-------------------|--------------|
| OSC_49M | 24.576 МГц | 49.152 МГц | Семейство 48kHz |
| OSC_45M | 22.5792 МГц | 45.1584 МГц | Семейство 44.1kHz |

GPIO1_D1 (MCLK_SEL) переключает между ними через `gpio-mux-clock`. Драйвер переключается автоматически в зависимости от частоты дискретизации.

## Настройка ПО

### Требования

- HQPlayer Desktop или Embedded
- Ethernet-сеть, соединяющая все ноды и хост HQPlayer
- Платы Luckfox Pico MAX с прошитой прошивкой

> **ОС для HQPlayer:** настоятельно рекомендуется Linux. Windows-версия HQPlayer генерирует рваный сетевой трафик, что может приводить к DMA underrun на одноядерном CPU RV1106, особенно на частотах дискретизации выше 192 кГц.

### Сборка

```bash
build.sh
```

Образ прошивки создаётся в `buildroot/output/images/`.

### Доступ к нодам

Подключение к любой ноде через SSH:

```bash
ssh root@<ip-ноды>
```

Пароль по умолчанию: `multisync`

### Конфигурация ноды

Каждая нода должна быть настроена как **master** или **slave** с помощью скрипта конфигурации:

```bash
/opt/configure.sh <источник_такта> <множитель_mclk> <роль>
```

#### Параметры

| Параметр | Значения | Описание |
|----------|----------|----------|
| источник_такта | `ext` / `pll` | `ext` = внешний генератор, `pll` = внутренний PLL |
| множитель_mclk | `512` / `1024` | Отношение MCLK к частоте дискретизации |
| роль | `master` / `slave` | Мастер или slave тактирования |

#### Примеры

**2 ноды, стерео bi-amping (внешний генератор 512fs):**
```bash
# Нода 0 — master (ВЧ + СЧ)
/opt/configure.sh ext 512 master

# Нода 1 — slave (НЧ + сабвуфер)
/opt/configure.sh ext 512 slave
```

**4 ноды с тактом 1024fs:**
```bash
# Нода 0 — master
/opt/configure.sh ext 1024 master

# Ноды 1, 2, 3 — slave
/opt/configure.sh ext 1024 slave
```

**2 ноды с внутренним PLL (внешние генераторы не нужны):**
```bash
# Нода 0 — master (PLL генерирует MCLK)
/opt/configure.sh pll 1024 master

# Нода 1 — slave (получает MCLK/BCK/LRCLK от мастера по проводам)
/opt/configure.sh pll 1024 slave
```

**Одиночная нода (без slave):**
```bash
/opt/configure.sh pll 1024 master
```

> **Примечание:** В режиме PLL мастер генерирует MCLK с помощью внутреннего PLL. Slave-ноды по-прежнему работают — они получают все такты (MCLK, BCK, LRCLK) от мастера по тем же проводам, что и в режиме EXT. Единственное отличие — источник тактирования на стороне мастера.

Скрипт:
1. Записывает режим тактирования и множитель MCLK в `/etc/i2s.conf`
2. Устанавливает hostname (`master` или `slave`)
3. Связывает соответствующий скрипт запуска networkaudiod
4. Настраивает синхронизацию времени Chrony (master раздаёт NTP, slave синхронизируется с master)
5. Прошивает правильный Device Tree Blob в NAND
6. Перезагружает ноду

### Настройка HQPlayer

Каждая нода отображается как отдельный NAA-эндпоинт в сети. Настройте многоканальный выход HQPlayer:

1. **Backend** Combo
2. **Devices** Выберите NAA-эндпоинт каждой ноды
3. **Каналы** 2, 4, 6 или 8 (в зависимости от конфигурации АС)
4. **Buffer time** 1 мс
5. **Trigger type** time

| Настройка HQPlayer | Значение | Примечание |
|---------------------|----------|------------|
| Backend | Combo | Объединяет несколько NAA-эндпоинтов |
| Channels | 2 / 4 / 6 / 8 | На каждый эндпоинт |
| Buffer time| **1 мс** | Критично — см. примечание ниже |
| Trigger type | time | Сетевая синхронизация |

> **Почему 1 мс?** В режиме Combo/Network HQPlayer отправляет обоим узлам абсолютный timestamp — «начни играть в момент T». При большом буфере (например 100 мс) момент T устанавливается на 100 мс вперёд: за это время накапливается расхождение системных часов между узлами, что приводит к рассинхронизированному старту. При 1 мс окно практически нулевое: узлы либо стартуют вместе, либо HQPlayer сразу видит промах и повторяет попытку. После начала воспроизведения аппаратная синхронизация I2S (общие провода BCK/LRCLK) обеспечивает точность до такта независимо от размера буфера.

**Combo backend** распределяет последовательные пары каналов по NAA-эндпоинтам. Пример для 3 нод по 8 каналов:

| Каналы | Нода 0 | Нода 1 | Нода 2 |
|--------|--------|--------|--------|
| 1–8 | SDO0–SDO3 | — | — |
| 9–16 | — | SDO0–SDO3 | — |
| 17–24 | — | — | SDO0–SDO3 |

### Проверенные конфигурации

| Режим | Каналов/Нода | Частота | Битрейт/Нода | Статус |
|-------|-------------|---------|--------------|--------|
| PCM 8ch | 8 | до 192 kHz | 49 Mbps | **Протестировано, стабильно** |
| PCM 4ch | 4 | до 384 kHz | 49 Mbps | **Протестировано, стабильно** |
| PCM 6ch | 6 | 384 kHz | 74 Mbps | **Протестировано, стабильно** (требуется Linux HQPlayer) |
| DSD 4ch | 4 | DSD64–DSD256 | — | Не тестировалось (драйвер поддерживает) |

> **Ограничение пропускной способности сети:** Каждая нода использует 100 Mbit Ethernet. Для стабильной многонодовой синхронизации необходим запас ~50% на TCP overhead и ретрансмиссии. Конфигурации, превышающие ~50 Mbps на ноду, могут постепенно рассинхронизироваться. Одиночная нода не подвержена этому ограничению (8ch/384kHz работает без проблем).

### Мощность выходных I2S пинов

Мощность (drive strength) выходных I2S пинов напрямую влияет на качество сигнала MCLK. Высокая мощность вызывает шум переключения, который проникает на вход MCLK через паразитные связи внутри RV1106 и создаёт видимый на осциллографе джиттер.

Скрипт `drv_strength.sh` позволяет изменять drive strength на лету без перепрошивки:

```bash
/opt/drv_strength.sh show    # Показать текущие уровни
/opt/drv_strength.sh 0       # Минимальная мощность (чистый MCLK)
/opt/drv_strength.sh 7       # Максимальная мощность (сильный сигнал)
```

| Уровень | Качество MCLK | Мощность сигнала | Рекомендация |
|---------|--------------|------------------|--------------|
| 0 | Лучшее | Минимальная | Короткие провода (< 5 см) |
| 2–3 | Хорошее | Средняя | Типичная установка |
| 7 | Худшее (джиттер) | Максимальная | По умолчанию (не рекомендуется для EXT) |

Скрипт управляет выходами BCK, LRCLK и SDO0–SDO3. Входы MCLK и SDI0 не затрагиваются. Выбранный уровень сохраняется в `/etc/i2s_drv_level` и автоматически применяется при загрузке.

Все элементы управления доступны в `/sys/devices/platform/ffae0000.i2s/`:

| Атрибут | Доступ | Описание |
|---------|--------|----------|
| `mute` | R/W | Аппаратное отключение звука (0/1) |
| `mclk_multiplier` | R/W | 512 или 1024 |
| `pcm_channel_swap` | R/W | Перестановка L/R каналов в режиме PCM |
| `dsd_physical_swap` | R/W | Перестановка L/R каналов в режиме DSD |
| `dsd_sample_swap` | R/W | Перестановка семплов DSD (исправление шума) |
| `freq_domain_invert` | R/W | Инвертировать GPIO тактового домена |
| `pinctrl_state` | R/W | Переключение пинов: `default` / `idle` |
| `tx_reset` | W | Сброс I2S TX |
| `postmute_delay_ms` | R/W | Задержка mute после старта (мс) |
| `frame_counter` | R | Монотонный счётчик фреймов |
| `drift_ppb` | R/W | Коррекция дрейфа тактирования (ppb) |
| `pointer_offset` | R/W | Смещение указателя DMA (фреймы) |

### Синхронизация времени

Ноды используют [chrony](https://chrony-project.org/) для точной синхронизации времени:

- **Master** синхронизируется с интернет NTP-серверами с очень медленным, безджиттерным слюингом (`maxslewrate 10 ppm`, опрос каждые 4–68 минут)
- **Slave** отслеживает master по локальной сети с частым опросом (каждые 4–32 секунды)
- Перед каждой сессией воспроизведения slave принудительно подстраивает время (`chronyc makestep`) для точной привязки к часам master
- Во время воспроизведения — только плавные частотные корректировки, без скачков времени

## Как это работает

1. **HQPlayer** отправляет многоканальное аудио по TCP/IP демонам NAA на каждой ноде
2. **networkaudiod** (NAA) принимает аудио и записывает в ALSA-устройство через `snd_pcm_writei()`
3. **ALSA/DMA** передаёт аудиоданные в TX FIFO периферии I2S
4. **Аппаратура I2S** сериализует данные на SDO0–SDO3, тактируясь общими BCK/LRCLK
5. Поскольку все ноды разделяют одни и те же физические тактовые сигналы, их выходы данных **побитово синхронизированы**

Драйвер I2S автоматически обрабатывает:
- Заглушение при смене формата (PCM ↔ DSD)
- Переключение тактового домена (44.1kHz ↔ 48kHz)
- Управление GPIO режима DSD
- Задержку старта мастера для синхронизации slave
- Изоляцию пинов в состоянии idle
